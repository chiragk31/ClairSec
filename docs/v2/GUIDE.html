ClairSec

Adversarial FastAPI Security Platform

Final Presentation Guide & User Manual

Covers: setup, the 7-minute demo, GitHub import, offline / no-internet operation,
every screen, the AI assistant, troubleshooting and panel Q&A.

One-line pitch: ClairSec attacks your API the way a real attacker would — inside a sealed box — proves what it finds, writes the fix, and proves the fix works. No AI is ever allowed to grade its own work.

1. What ClairSec does

You give ClairSec a FastAPI project (a local folder or a GitHub URL). It runs a five-stage pipeline:

StagePlain wordsWhat really happens
BuilderReads your app and maps every door into it.Static route extraction + OpenAPI from the running app, test users provisioned.
AttackerTries those doors like a real attacker — safely.Sends real requests through a scope-locked client to the sandboxed app.
EvaluatorDouble-checks every attack with hard rules.Deterministic oracles (code, not AI) decide; reproduces each finding; CVSS computed by code.
FixerWrites a code change that closes the door.Unified diff applied only to a copy of the project (original never touched).
VerifierTries the attack again and checks the app still works.Builds the patched app in its own container; three proofs: exploit blocked, app still works, endpoint preserved.
The rule that makes it trustworthy: AI models only propose tests and patches. Every verdict — confirmed, severity, score, "fix verified" — is computed by platform code from recorded requests and responses.

Key features to show

  • GitHub import — paste a URL; safe tarball download (size, file-count, path and symlink checks), file tree, commit SHA, import notes, and exposed-secret detection (API keys/tokens/passwords found, shown masked).
  • Autopilot — one click: import → sealed container → scan → fix → verify → report.
  • Live attack timeline, agent cards and attack-surface map.
  • Security score before → after verified fixes (e.g. 55 D → 100 A), with honest "limited coverage" notes.
  • "Why you can trust this finding" — the evidence chain: AI proposal → request sent → oracle fired → reproduced → CVSS → fix verified.
  • Exploit replay — re-send the same attack to the original app (works, HTTP 200) and the patched app (blocked, HTTP 403).
  • Three-proof fix review — exploit blocked · app still works · endpoint preserved.
  • Reports — PDF, HTML, Markdown, JSON and SARIF (GitHub code scanning format); executive page + technical detail.
  • Ask ClairSec (Ctrl+J) — AI assistant on every screen, grounded in recorded data, with citations; it cannot change anything.
  • Themes — light/dark, 5 colour presets, responsive layout, Presenter mode (F11).

2. Setup (once)

  1. Docker Desktop — start it and wait for "Engine running". If it hangs: quit Docker Desktop, run wsl --shutdown in PowerShell, start Docker Desktop again.
  2. MongoDB — the clairsec-mongo container (already on this PC) starts with Docker. If MongoDB is not running the backend still works on temporary in-memory storage (badge: TEMPORARY STORAGE).
  3. Backend packages (already installed in venv): 
    cd D:\ClairSec\backend
..\venv\Scripts\python.exe -m pip install --require-hashes -r requirements.txt
  4. Flutter: cd D:\ClairSec\desktop then flutter pub get.
  5. AI (optional) — without a key ClairSec uses its offline assistant and offline AI automatically. For live AI put LLM_PROVIDER=anthropic and LLM_API_KEY=... in backend\.env, or install Ollama, ollama pull <model>, and set LLM_PROVIDER=ollama + OLLAMA_MODEL=<model>.

3. Start it (every time)

:: Terminal 1 — backend
cd D:\ClairSec\backend
..\venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

:: Terminal 2 — desktop app
cd D:\ClairSec\desktop

8. Ask ClairSec (AI assistant)

  • Open with the ✦ button or Ctrl+J. It knows the screen you are on (scan, finding, fix…).
  • Tap a suggested question or type your own; switch on Explain simply for non-technical answers.
  • Answers show citation chips (the records used) and links you can click; it never changes anything.
  • Without an AI key it is the Offline assistant (deterministic, from recorded data). With a key it writes the prose, but answers that cite nothing or claim an app "is secure" are withheld by platform code (this was caught live with a small local model following an injected instruction).

10. Questions the panel may ask

"Isn't this just ChatGPT finding bugs?" No. The LLM only proposes tests and patches; oracles (code) decide. Show the evidence chain on a finding.

"How do you know the fix didn't break the app?" Three proofs: the exploit is re-run and blocked, the app's checks still pass (its own tests, or read-only checks generated from its OpenAPI schema and compared to before the fix), and the route still exists. Otherwise the fix is marked regressed or unverified, never "fixed".

"Is it safe to scan a random GitHub repo?" It is downloaded as a tarball with size, file-count, path and symlink checks, and runs only inside a hardened container (no capabilities, read-only filesystem, internal network). Only ClairSec's own demo apps ever run directly.

"What did you find in secrets?" Keys committed to the repo are detected and shown masked — we never display a working key.

"What is novel?" Verified-fix proof (blocked + still works + endpoint kept), an injection-resistant grounded assistant, and a fallback chain that never fakes data.
